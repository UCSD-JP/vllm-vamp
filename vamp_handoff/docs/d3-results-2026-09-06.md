# D3 Actual GPU KV over Shared CXL

## Status and Scope

D3 functional feasibility PASS on solab s1 -> s2. Implemented by Codex after
explicit user authorization to design, implement and test on both nodes.
Base commit: `7a01f560f`. New code is under `vamp_handoff/solab/d3_*.py`;
the provider, installed vLLM/Dynamo files and SOURCE_LOCK are unchanged.

This is a single-session, single-transfer, idle-worker feasibility adapter, not
a routing policy, pressure experiment, or production connector. Source GPU KV
is pinned, gathered into bounded GPU staging, DMA-written to registered CXL,
then DMA-read and scattered into reserved B GPU blocks. B's GPU prefix index
is populated only after full-payload SHA256 equality. CPU import is not used.

## Configuration

- Two independent RTX A6000 workers, Qwen3-14B BF16, TP=1, MML=16,384, MNS=16,
  utilization=0.90. CPU offload 64 GiB remains enabled in both arms.
- Each GPU pool: 6,097 blocks x 16 tokens = 97,552 tokens.
- GPU KV canonical layout: **one** int8 tensor, 2,621,440 bytes per block;
  cross-layer allocation `(6097, 40, 2, 16, 8, 128)`.
- Staging: 133,693,440 B = 127.5 MiB per GPU, also allocated in B0.
- Thus the actual installed layout is NOT 64,000 independent DMA pieces.
- Fixed namespace endpoints: vampA:8080 -> s1, vampB:8081 -> s2. Cold worker
  reset per cell; CXL manager, etcd, nats and frontends retained.
- Integrity readback and SHA256 are enabled and included in total time.

## Matched Large-Prefix Results

One measurement per arm. Identical salt `e1`, actual prompt 13,819 tokens and
9 output tokens. Do not call this the old 12,821-token cell: salt tokenization
changed the size. Source exports 861 complete GPU blocks = 13,776 tokens;
43 prompt tokens remain for B to compute. Payload = 2,257,059,840 bytes.

| Metric | B0 recompute | D3 direct, full verification |
| --- | ---: | ---: |
| A cold response | 4.544 s | 4.540 s |
| Preparation after A response, including readiness/control nudges | 0.139 s | 9.106 s |
| B first response after dispatch | 4.579 s | 0.563 s |
| Gap=0 arrival-to-response-complete | 4.718 s | 9.670 s |
| B subsequent GPU-warm response | 0.547 s | 0.544 s |
| B first GPU hit tokens | 0 | 13,776 |
| B first CPU external hit tokens | 0 | 0 |
| Marker / cleanup gates | PASS | PASS |

Direct preparation breakdown (17 chunks, same digest at A and B):

| Component | A export | B import |
| --- | ---: | ---: |
| Registration | 0.104 s | 0.091 s |
| Gather / scatter | 0.013 s | 0.013 s |
| GPU->CXL / CXL->GPU DMA | 0.309 s | 0.231 s |
| Fence / refresh | 0.167 s | 0.166 s |
| Verification, including GPU readback | 4.181 s | 3.170 s |
| Unregister | 0.039 s | 0.041 s |
| Full owner-thread operation | 4.984 s | 3.777 s |

The critical distinction: **B actually reuses imported GPU KV, but the full
verification implementation is slower than recompute at gap=0.** Subtracting
verification is not a measured checksum-free result. No checksum-free mode or
performance claim is made. Native eager CPU offload still runs; the migration
payload itself bypasses private CPU staging. Debug readback is separate traffic.

## Reproduction and Rollback

Run on s2 with its existing venv (deploy `solab/d3_*.py` into `~/vamp/probe/`
on the applicable nodes first):

```bash
~/venvs/dynamo05_vllm019/bin/python ~/vamp/probe/d3_reset.py
~/venvs/dynamo05_vllm019/bin/python ~/vamp/probe/d3_suite.py
```

The suite resets between its three cells; run `d3_reset.py` first for its
initial cell. It stops at the first failure and archives the failed cell.
For a normal staged-path worker, use the existing launcher with
`SPEC_MODULE=vamp_agent`. D3's monkey patches exist only in D3 worker processes.
